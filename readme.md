\# Bank Data Assistant



Ask questions about banking data in plain English. An LLM (via the Ollama Cloud API) writes the SQL, and the app runs it against a SQLite database and shows the results as a table and chart.



> All data is \*\*synthetic\*\*, generated by `generate\_bank\_db.py`. No real customer data is used.



\## Features

\- Natural language to SQL over 5 tables: branches, customers, accounts, transactions, loans

\- Safety checks: SELECT-only validation, single-statement rule, read-only database connection

\- Automatic retry: if the SQL fails, the error is sent back to the model for one correction

\- Table results, bar chart, and optional plain-English summary

\- Prompt includes schema and banking terms (NPA categories, KYC status)



\## Tech stack

Python, Streamlit, SQLite, pandas, Ollama Cloud API



\## Setup



1\. Clone the repo and install dependencies:

&#x20;  ```bash

&#x20;  git clone https://github.com/vaishnavisndrm/bank-data-assistant.git

&#x20;  cd bank-data-assistant

&#x20;  pip install -r requirements.txt

&#x20;  ```

2\. Create the sample database:

&#x20;  ```bash

&#x20;  python generate\_bank\_db.py

&#x20;  ```

3\. Add your Ollama API key. Copy `.streamlit/secrets.toml.example` to `.streamlit/secrets.toml` and put your key in it.

4\. Run the app:

&#x20;  ```bash

&#x20;  streamlit run app.py

&#x20;  ```



\## Example questions

\- Top 5 branches by total account balance

\- Total NPA outstanding by loan type

\- Monthly UPI debit volume in 2026

\- Customers with more than 2 active accounts



\## How it works

1\. `schema.sql` plus business notes go into the system prompt.

2\. The model returns one SQL query.

3\. The query is validated and run on a read-only connection.

4\. Results are shown in the UI.



\## Notes

This is a demo. For real customer data, use a private or local model deployment, access control and audit logging.
